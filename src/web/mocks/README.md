# Local mock transport

`runs.json` contains one canonical queued RunListEntry in its bounded envelope. `runOptions.json` contains the bounded fake runner/build/profile/suite options and repetition limits. Generated Zod validators parse both before any handler can serve them. Pydantic can validate the same JSON bytes.

The earlier `createFixtureHandlers` export remains available for metadata/list consumers. P03 uses `createRunsDemo` and `createRunsHandlers` in `runsDemo.ts`, with generated operation paths and request/response validators. Handlers implement search/execution/outcome filters, bounded cursor pages, dependent run options, eligibility rechecking and mock creation. Historical PASS/FAIL/INCONCLUSIVE rows are synthetic fixed fixtures. New submissions remain QUEUED / NOT_EVALUATED; components never advance a lifecycle with a timer.

The mutable demo scenario supports ready/loading/empty/error/invalid reads and accept/reject/committed-but-malformed acknowledgment submissions. Loading adds transport delay and still permits valid admission. The Malformed acknowledgment once control commits the receipt and row, deliberately returns an invalid first acknowledgment, and returns the original valid receipt on replay. Invalid deliberately bypasses fixture validation to exercise the client rejection boundary; malformed data is not a valid domain fixture. The top controls are explicitly demo controls. A fresh page reload restores the initial session; created mock rows and idempotency receipts are in memory only.

Mock creation validates the project, header/version, body/bounds, current available runner/build/profile and eligible published suite. Receipt lookup precedes current eligibility checks so recovery remains possible with empty/error options. An unchanged key/payload replays its original response; changed payload returns 409. Rejected admission creates no row. These are local demo semantics, not authentication, durable 24-hour idempotency, a real queue, capability qualification or production cursor guarantees. No backend, runner, simulator or arbitrary script is invoked. Unknown same-origin `/api/*` requests receive a mock 501 instead of reaching a live service.

`browser.ts` starts MSW explicitly before the application renders. `pnpm --filter @featherlane/web prepare:mocks` regenerates `public/mockServiceWorker.js` from pinned MSW; dev and build invoke it automatically. The worker asset is ignored and must not be committed. No test harness, test worker, snapshots or coverage scaffolding is introduced. MSW 3 uses `onUnhandledFrame`; non-API static assets are bypassed.

## P04 detail transport

`runDetail.json`, `runArtifacts.json` and `runEvents.json` are bounded canonical envelopes, validated by Pydantic during preparation and generated Zod validators on import. `runDetailFixtures.ts` creates explicitly selected synthetic snapshots from that seed and the actual admitted inputs. It does not evaluate real telemetry. Run/attempt/trial/artifact/event references are scoped consistently. ERROR/CANCELED retain NOT_EVALUATED aggregate outcomes; missing observations never produce PASS; expiration keeps a completed run's historical outcome. The server-side demo immediately cancels queued work with a 200 CANCELED/NOT_EVALUATED receipt and no execution attempt/evidence; active work records intent with 202 and remains active. It stores intent and keyed receipts in memory. Replaying an acknowledged request returns its original receipt; selecting a new fixture is an explicit demo reset, not lifecycle progression.

`runDetailDemo.ts` handles the generated detail, JSON-event, artifact-metadata and cancellation paths before the existing mock fallback. It validates versions, IDs, query/body/header shapes and cursor bounds. Unknown resources use canonical 404, expired/foreign cursors use 410, and unsupported versions use 400. Reads/mutations run through the validated public SDK before Query sees the result. The metadata-only Python route declarations are for generation, not a runnable business API. There are no binary streams, raw uploads, SSE, simulator processes or real authorization guarantees in this fixed demo scope.

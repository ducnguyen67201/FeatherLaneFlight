  explicit limit. Preserve check identity, kind, units, version and evidence.

  revisions. Existing duration restoration remains available for an older draft

  validators plus identity/version/evidence checks reject unsupported input.
  Saved version, captured content and a monotonic local edit counter guard every
  acceptance, including a value edited and then restored. Busy/conflict/access
  guards remain in the editor's change boundary.

  requirements and availability. GET/POST on the project/suite draft's
  `criteria-suggestions` route reuses existing live session, same-origin CSRF and
  memberships. Recheck authorization/version after external I/O; no database
  transaction is held during generation. Suggestions never persist or publish.
- OpenAI adapter uses `gpt-6.1-sol`, low reasoning, standard service, 30-second
  timeout, 2,048 output tokens, 64 KiB response cap, no tools/retries and
  `store: false`. Canonical Pydantic types derive the structured-output schema;
  authoritative validation follows. Safe failures never echo raw provider errors.
- [Project TOML](../../../config/criteria-generation.toml) is loaded once, with an
  explicit CLI file override. Criteria settings/credentials are not environment
  variables. Key-file paths resolve relative to the TOML directory; key contents
  must be a bounded owner-only regular file. No key file was created or supplied.
  Live generation defaults **off**. Per-process concurrency/session guards are
  not distributed quotas or account spend caps.

  ledger, executable rule or PX4 capability. No tests, snapshots, coverage targets
  or permanent verification scaffolding were added.

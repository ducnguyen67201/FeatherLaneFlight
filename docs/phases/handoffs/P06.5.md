## Behavior and boundaries

- AuthBoundary owns the epoch-keyed QueryClientProvider. P07 receives only
  canonical session-derived values, the epoch-bound validated client, auth cache
  prefix and callbacks. Project queries stay scoped to identity/org/project.
- Session/bootstrap and logout use generated SDK/Zod/Query policies. Google uses
  the generated native navigation policy, never a JSON redirect fetch.
- Auth identity/CSRF rotation, logout and 401 retire the previous client, cancel
  reads, clear protected query/mutation caches and replace QueryClient. Late
  responses/callbacks cannot affect the next epoch. P07 owns 403/404 access recovery.
- Same-origin transport clones validated headers, supplies in-memory CSRF on
  mutations, disables JSON redirects/caching and leaves cookies HttpOnly. Nothing
  writes credentials or a persistent query cache to browser storage.
- Logout hides project content before sending. Uncertain failure stays locked;
  retry refreshes current session/CSRF. Already-ended sessions return to sign-in.
  Pending/error screens match the specifically approved rendered preview.
- Development origin is `http://127.0.0.1:4248`; API binds only to `127.0.0.1:8009`.
  Both `/api` and `/auth` proxies preserve browser Host/Origin (`changeOrigin:false`,
  `xfwd:false`). Callback is `/auth/google/callback`; canonical return is `/`.
- Explicit `dev:demo` serves the preserved sample application at loopback4200,
  without an API proxy. Production builds always select the real auth entry.
  No backend auth bypass, invented DTO/path, role model, simulator or stream
  framework was added. There are no current application SSE streams to close.

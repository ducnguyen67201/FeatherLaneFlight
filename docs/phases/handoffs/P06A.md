## P07 integration seams

`featherlane_api.modules.identity.domain.Principal` is a frozen dataclass:

- `user: User` (frozen `id: str`, `display_name: str`, `email: str`).
- `session_id: str` (internal identifier, never the opaque cookie).
- `expires_at: datetime` (UTC aware).
- `user_id: str` property returning `user.id`.

In `modules.identity.dependencies`:

- `get_principal`: FastAPI read dependency; current session/user lookup and short
  read transaction complete before returning Principal.
- `require_csrf`: mutation dependency; validates the exact canonical request
  origin, a single `Origin`, fetch-site when supplied, and one session-bound
  `X-CSRF-Token`; returns Principal with no transaction left open.
- `get_identity_service`: builds the request service using the same cached P05
  `http.dependencies.get_session` AsyncSession as consumer services.
- `session_handle(request) -> str | None`: canonical cookie parsing seam. Use it
  in the HTTP adapter; do not copy cookie names/parsing, log the handle, put it in
  a DTO, or ask application services to import Request.

Consumer mutation sequence: depend on `require_csrf`, obtain the same request
session/service and `session_handle(request)`, then begin the consumer service's
`async with session.begin():`. Inside it call
`await identity_service.require_live(principal, handle)` before checking both
current memberships and writing. Optional `csrf` checks it again in the write
transaction when needed; it does not replace the HTTP dependency.

`require_live` requires an already-open transaction, checks current session ID,
user ID, user activation, expiry and revocation, refreshes identity-map state and
locks both session/user via `FOR UPDATE` until caller commit. It neither begins
nor commits the caller transaction. Revocation blocks on that lock and is visible
to subsequent requests. P07 must recheck both membership tables in this same
transaction and use the non-disclosing resource policy. A Principal grants no
membership. Reference `featherlane.users.id`; follow `0002_identity`, reuse Base,
and never import identity ORM mappings as access logic.

## Dependency interfaces and integration requirements

Exact paths and signatures are documented in `src/api/README.md`:

- `featherlane_api.app.create_app(settings: ApiSettings | None = None) -> FastAPI`.
  Register phase-owned routers via `app.include_router`. Settings are available
  as `app.state.settings`; lifespan supplies `app.state.database`.
- `featherlane_api.config.ApiSettings`/`load_settings()` use `FLF_API_` variables;
  required runtime values are database URL, canonical origin and artifact root.
  `DatabaseSettings`/`load_database_settings()` are the migration-only subset.
- `featherlane_api.infrastructure.database.Base` owns the `featherlane` metadata schema and
  naming conventions. `Database.session_factory` is an
  `async_sessionmaker[AsyncSession]`. `featherlane_api.http.dependencies.get_session(request)` yields one session
  and closes/rolls back uncommitted work; it never auto-commits.
- A service owns `async with session.begin():` including live authorization,
  writes and audit before success. Read/auth dependencies finish their read
  transaction before returning a principal, so SQLAlchemy autobegin cannot
  collide with a later mutation transaction. Recheck active principal/organization/project membership
  in that write transaction. Never silently roll back another layer's work.
- `featherlane_api.http.errors.ApiError(status, code, message, details=())`,
  `ERROR_RESPONSES`, and `install_error_handlers(app)` provide canonical errors;
  messages/details must be safe application-owned text.
- Migration root is `0001_foundation`. P06A follows it with its actual identity
  revision; P07 follows that revision. P06 is UI-only under the latest master scope. Both use the shared Base, importing actual
  domain models in Alembic before autogeneration/check. Central settings/router/
  model imports and lockfile changes are reconciled by the master.
- `featherlane_api.modules.evidence.ports.PrivateArtifactStorage`/`StoredArtifact` are internal
  ports only. P16 must implement actual private storage/upload flows and their
  streaming/authorization/quota/verification requirements.

## Approved architecture refactor

The human explicitly approved the proposal in this chat: “Yes, let's use this
architecture. Refactor the current backend into that structure and coordinate
the new import paths with the master so P06 and P07 follow it too.” This approves
the local refactor; it does not approve phase publication.

Implemented the existing foundation as a domain-oriented modular monolith:

- `http/` owns HTTP errors/middleware, the public metadata router, and request
  dependencies. `http/dependencies.py` now owns FastAPI's `get_session` adapter.
- `infrastructure/database.py` owns the same SQLAlchemy Base, engine and session
  factory with no FastAPI imports. Transaction behavior is unchanged.
- `openapi/schema.py` and `openapi/export.py` own resource-free metadata/export.
  `scripts/contracts.mjs` uses `featherlane_api.openapi.export`.
- `modules/evidence/ports.py` owns the existing private artifact storage port.
  No empty future domain modules, new business endpoints, generic repositories
  or duplicate DTOs were introduced.
- `app.py` remains the composition root; `http/meta.py` reads the compiled digest
  from `app.state.schema_digest`. `cli.py` and `config.py` keep their import paths.
- The API README documents the implemented layout, future module ownership,
  inward dependencies, transaction rules and concrete imports.

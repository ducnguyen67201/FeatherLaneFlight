## Implemented scope

The approved P03 Runs screen retains its list, filters, columns, pagination and New Run modal. Open now follows an ordinary `/runs/:runId` link, with local navigation for normal clicks and Back/history support. Search, execution/outcome filters and cursor/page context stay in RunsWorkspace across detail navigation, browser Back and Runs links. Direct detail entry retains a logical return target. Returning to the list restores focus to the opened row when present, with the persistent New Run button as fallback.

Run detail composes focused status, trial/check, frozen manifest, terminal-style event log and artifact metadata components. Requested and observed manifests remain separate; queued runs have no observed manifest. The selected trial and its attempt scope observations, checks, events and artifacts; attempt-wide entries remain visible only for that same attempt. Counts and outcomes come from validated snapshots. The UI does not evaluate metrics or infer passing outcomes from absent values. Missing/expired evidence, stale refreshes, loading/empty/request errors, FAIL versus ERROR/INCONCLUSIVE and cancellation states remain distinct.

Canonical Pydantic inspection models live in `featherlane_contracts.run_detail`: bounded manifests/checks, attempts/trials/observations/results, artifact metadata, event records/pages and cancellation request. Metric/flag observations and check kinds use discriminated unions; metric checks require a numeric threshold. Generated schemas/types/validators/client/keys remain ignored. Public SDK wrappers validate final transformed results and status-aware wire data before Query caching. The four new HTTP declarations are metadata only; no business backend was introduced.

Three canonical JSON fixture envelopes seed deterministic MSW snapshots. Newly admitted queued runs retain their actual build/profile/suite/repetition inputs. Server-side mock modes author the selected synthetic snapshots; browser components never manufacture domain outcomes. Run/attempt/trial/artifact/event references are scoped and event sequences remain contiguous. Historical completed outcomes survive raw evidence expiration. The retained P03 infrastructure-error sample now has aggregate NOT_EVALUATED, matching the canonical state vocabulary; historical completion times were aligned with the bounded repetition evidence.

Cancellation has a pending guard and stable idempotency key. Queued cancellation is an explicit immediate MSW-server CANCELED/NOT_EVALUATED response (200), with the same stored replay receipt, no started time, attempt, observed manifest, trial, artifact or event, and unchanged requested inputs. Active cancellation returns 202 intent without inferring process exit. Acknowledged intent invalidates lists/details/events/artifacts without inventing stopped execution. Uncertain acknowledgment retries preserve the key; terminal runs preserve their original outcome. Mock responses show rejection, delay and requested/unconfirmed/confirmed snapshots separately. There are no lifecycle timers or live process controls.

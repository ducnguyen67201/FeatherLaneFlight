## Implementation

- Canonical `featherlane_contracts/evidence.py` supplies bounded declarations,
  receipts, local upload policy and allowlisted process diagnostics, reusing P13
  attempt/lease identities and existing artifact/observation contracts. Artifact
  availability adds LOCAL_ONLY, never VERIFIED by implication.
- The API evidence module provides private staging, incremental quota enforcement,
  full-stream size/SHA-256 verification, immutable declarations/receipts and
  publication under current authenticated attempt/lease/fence authority. It checks
  authority after filesystem publication before exposing verified metadata.
- Terminal identical receipt recovery does not renew execution or permit new
  writes. Revoked credentials fail. Corrupt/disallowed/partial bytes never become
  downloadable. Storage keys are server-issued opaque IDs, not client paths/URLs.
- Browser metadata and attachment reads require a current session and explicit
  project membership. Content must be VERIFIED, upload-backed, retained and
  physically present. Membership/retention are checked per 64 KiB stream chunk.
  Attachments use fixed filenames, no-store, nosniff and declared lengths.
- Settings/startup/middleware/schema wiring preserve ordinary JSON bounds and
  whitelist only the canonical binary upload route. Migration 0016 follows actual
  0015; the tail is 0013 -> 0014 -> 0015 -> 0016 with one head.
- Authorized RunDetail evidence totals use the same bounded records and availability
  projection as artifact listing, preserving P15's signed cursor and P14 usage.
- Runner evidence preparation uses policy-allowed fixed filenames, held no-follow
  descriptors, owner-only files and actual P14 closed-output identity/hash proof.
  It leaves original removal and reservations with P14. The upload transport reuses
  the existing pinned-origin runner client and bounded JSON receipt decoder.
- `scripts/contracts.mjs` emits separate binary policies. The public TypeScript
  `readArtifactContent` operation derives its route/method from those generated
  policies and uses canonical validators plus current client/session guards. JSON
  SDK interceptors do not consume binary attachments.
- `useEvidenceDownloads` refreshes current metadata in the existing scoped Query
  cache before downloading, aborts on context disposal, reuses P15 snapshot cadence
  for artifact freshness and uses existing access-loss clearing. It preserves P15
  transport/cache/freshness/reconnect/cancellation ownership.
- The binary client requires an unexpired VERIFIED/AVAILABLE record, same-origin
  cookie request, attachment filename, matching media type/length and nosniff.
  Complete bytes and SHA-256 must match before any Blob/object URL is saved. Reads
  are bounded to 100 MiB, errors to 64 KiB, and content transport to 60 seconds.
  Partial, corrupt, oversized, redirected or stale-context data creates no file.
- The approved React/MUI Evidence component was promoted from the interactive
  preview, with the metadata dialog extracted by responsibility. Loading, empty,
  refresh-error, download-error, access-loss, missing, expired, failed, pending and
  local-only states remain explicit. Refresh errors disable downloads; access
  loss unmounts protected content/dialogs. Only current valid files can download.
- The approved compact timeline uses recorded attempt/trial boundaries, slim bars,
  keyboard targets, two-axis scrolling, density/zoom and pause/catch-up. Missing or
  conflicting boundaries stay unavailable. No browser-clock extrapolation, arbitrary
  span protocol, evaluator, video or fault diagnosis was added.
